# Implementation Plan: Update Results Query Schema for Structured Verdict

**Branch**: `CIMD-3915-results-verdict-schema` | **Date**: 2026-06-16
**Spec**: [spec.md](spec.md) | **Research**: [research.md](research.md) | **Data model**: [data-model.md](data-model.md) | **Contracts**: [contracts/query-schema-contract.md](contracts/query-schema-contract.md)

## Summary

Update the staging prosecutors query-API contract schema (`hmcts.results.v1.json`) to reference the results context's new local `prosecutorResult.json` schema (introduced in CIMD-3915), which adds a structured `verdict` object on offences. Also update the example file to demonstrate the verdict shape. No Java production code changes are needed — `ResultsQueryApi` is a pure pass-through. This is a two-file contract documentation update.

## Implementation Phases

### Phase 1 — Schema File Update

**Single file, single change. No Java. No tests to write.**

**1.1** Update `stagingprosecutors-query/stagingprosecutors-query-api/src/raml/json/schema/hmcts.results.v1.json`:

Change `"ref"` from:
```json
"ref": "http://justice.gov.uk/core/courts/informantRegisterDocument/prosecutorResult.json"
```
to:
```json
"ref": "http://justice.gov.uk/results/courts/informantRegisterDocument/prosecutorResult.json"
```

Full file after change:
```json
{
  "$schema": "http://json-schema.org/draft-04/schema#",
  "id": "http://justice.gov.uk/stagingprosecutors/query/stagingprosecutors.query.results",
  "ref": "http://justice.gov.uk/results/courts/informantRegisterDocument/prosecutorResult.json"
}
```

**Gate**: Read the file and confirm the single-line change is correct before proceeding.

---

### Phase 2 — Example File Update

**1.2** Update `stagingprosecutors-query/stagingprosecutors-query-api/src/raml/json/example/hmcts.results.v1.json`:

Add a `verdict` object to the first offence of the first defendant. Keep the second defendant's offence **without** a `verdict` field (demonstrating optionality).

Target diff on the first offence (under defendant `Fred Smith`):

```json
{
  "offenceCode": "PS90010",
  "orderIndex": 1,
  "offenceTitle": "Public service vehicle - passenger use altered / defaced   ticket",
  "pleaValue": "NOT_GUILTY",
  "verdict": {
    "verdictCode": "G",
    "verdictDate": "2020-03-12",
    "verdictType": "FOUND_GUILTY"
  },
  "offenceResults": [
    {
      "resultText": "Pay by date /n Reserve Terms Lump sum"
    }
  ]
}
```

The second defendant's offence (`Fred Daligarce`) is left **unchanged** — no `verdict` field — to demonstrate that verdict is optional.

**Gate**: Read the updated example file and verify:
1. First offence contains `verdict` with `verdictCode`, `verdictDate`, `verdictType`
2. Second offence has no `verdict` field
